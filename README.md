# HPLC Run Decision Tool

Open [index.html](./index.html) in a modern browser and choose a CSV or XLSX exported from a chromatographic run. XLSX conversion uses the SheetJS browser bundle loaded from jsDelivr, so an internet connection is needed for XLSX files.

## Exporting a chat transcript to PDF

Use Node.js and Microsoft Edge or Google Chrome to convert a VS Code Agents `chat.json` export. The PDF is saved beside the JSON file by default, and every page is stamped with `Yenuli DIAS SENEVIRATNE`:

```powershell
node .\convertchattopdf.js .\chat.json
```

You can also pass a second argument to choose the PDF output path:

```powershell
node .\convertchattopdf.js .\chat.json .\chat-transcript.pdf
```

## CSV input

The importer understands LabSolutions CSV exports (including the `[Peak Table(PDA-Ch1)]` and LC status sections) and standard header-row CSV files. It extracts:

- The method name from the sample name/B20-style value using `GR{Group No.}-{Injection No.}-{HPLC No.}-{Solvent Type}-{PH No.}-ISO-{%B}-{Flow Rate}-{Injection Volume}[u]-{CP/BLK}{Sample Concentration}-{Ligand}[Column Type]-{Column Length}x{Column Internal Diameter}x{Particle Size}-{Temperature}-{Wavelength}`. The injection-volume `u` and separator before the column-type code are accepted with or without the optional punctuation used in different exports. The Group No. and Injection No. are retained, with Injection No. used as the Trial No.
- Parameter values are read from the method name and from exact label/value rows in LabSolutions exports. For simple tabular CSVs, column headers on the first row are also supported. This avoids interpreting later trace-section headings as parameter values.
- For LabSolutions files, the method nomenclature in `Sample Name` is compared with the method name in `Data File Name`. Comparison is case-insensitive and compares parsed values so optional units such as `u` and `nm` do not cause a false mismatch. Different run identifiers or method settings show `Evaluate Naming Nomenclature: Do Not Match / Please Submit File with Corrected Naming Nomenclature` in the matching trial's Actions cell. The warning is informational: parsed sample-name values still feed the decision engine and calculations. CoreShell is assigned automatically: Ultra is Yes, and other column types are No.
- Peak count, total retention time, the lowest positive peak resolution, pressure, and measured temperature.
- Retention times are read from the column titled `R.Time` inside the `[Peak Table…]` section; the parser resolves columns by their header names rather than assuming fixed positions. These exact peak-table values are used for peak retention analysis. Peak data is noise-filtered in memory before analysis: rows with an `Area` below `80,000 AUC` are excluded from calculations, while the uploaded CSV/XLSX is never modified.
- The `Extraction log` panel shows raw and filtered peak counts, each peak's area/threshold/keep decision, and the derived run values. The same information is also written to the browser developer console.
- Back-pressure is calculated from the Pump A pressure trace by averaging every intensity value in its variable-length `R.Time (min), Intensity` table, then multiplying that average by the section's `Intensity Multiplier`.
- The final back-pressure value is rounded and displayed to three decimal places.
- Set Temp is the programmed temperature parsed from the method/file name; `amb` is displayed as 25°C. **An ambient run is defined as a run with Set Temp = 25°C.** Measured Temp does not determine ambient status. Measured Temp is a separate value calculated from the `[LC Status Trace(Oven Temp.)]` section by averaging timestamped temperatures from the trace start (time 0 or the first non-negative timestamp) through the extracted total retention time. The measured average is rounded to two decimal places. If the trace is unavailable, only an explicitly labelled measured-temperature field is used as fallback; Set Temp is not substituted. The Trials table shows separate `Set Temp (°C)` and `Measured Temp (°C)` columns. Suggested rows leave Measured Temp blank because they have not been run. The trace range, sample count, and average are written to the Extraction log. Ambient-run analysis uses Set Temp, not Measured Temp.

Each upload appends one row to the Trials table. Method parameters encoded in the run name are parsed independently from the CSV/XLSX `Sample name`, its embedded `Data file name`, and the uploaded file name. Each parameter uses the value supported by the most available sources (majority agreement); equivalent numeric values, ambient temperature, and common methanol abbreviations are normalized before comparison. If sources conflict, the first source in that order breaks a tie and the conflict is recorded in the Extraction log and flagged on the trial row. These reconciled method-name values take precedence over single-source labeled values in the file. Changing a method specification recalculates all recommendations.

The measurements panel is labelled `Current viewed run`. It remains blank until a source-trial row is highlighted; uploading a file does not automatically select the run. Click any uploaded source-trial row to view that run's parameters, measurements, and decision; suggested rows are not selectable source runs. The Column & Flow Parameters table is blank until a run is uploaded. Column Type is read from the method filename: `P` becomes Pinnacle, `U` becomes Ultra, `F` becomes Force, and `R` becomes Raptor. The detected Column Type is copied to the Trials table and suggested rows. Core-shell is derived from Column Type: Raptor is Yes, and other column types are No. Pore Size and C-Load are directly editable text fields for every uploaded run. If any uploaded run has a conflict between parsed naming sources, the Column & Flow Parameters form becomes editable for every uploaded source run; select each source-trial row to edit that run. Edits update the selected source trial and its suggested rows in the Trials table.

## Equipment tab

The Equipment tab is titled `HPLC Modules Guide` and contains an interactive schematic with clickable regions and tabs for Solvent Bottles, Degasser, Pump, Manual Injector/Autosampler, Column/Column Oven, and Detector. Selecting a module updates its parameter dropdown. Selecting a parameter displays its function, category, instrument control point, units, allowed/typical range, and concise scientific effects on retention, selectivity, efficiency, and system operation. The Pump view compares binary and quaternary solvent-mixing arrangements, each with its schematic beside the matching instrument photo: binary systems mix after the pumps at high pressure, while quaternary systems proportion solvents before the pump at low pressure. When the Manual Injector/Autosampler module is selected, labeled Manual Injector and Autosampler buttons below the HPLC schematic switch between the corresponding supplied photo. It explains when parameters may be changed and whether the decision engine recommends changing them. The Degasser is identified as a non-adjustable stability module with fault indicators. Instrument-specific limits are identified as such rather than guessed. Reference information is based on the supplied parameter-reference CSV files and is preloaded in the equipment lookup data near the beginning of `app.js`.

For `Jump to Minimum %B OR Intermediate %B`, the Trials table shows one prediction row with a `%B` dropdown containing the calculated Minimum `%B` and Intermediate `%B` values, displayed as percentages only. For `Jump to Minimum %B THEN, Intermediate %B`, it shows two fixed prediction rows, one for each calculated value. After the required ambient minimum and intermediate runs, downstream temperature/solvent stages create prediction rows with editable `%B` dropdowns.

Each later stage requires a deficient run at every distinct `%B` value recorded in the preceding stage, in the same sequence. The stages are: original solvent at 40°C and 60°C; the alternate solvent (ACN or METHANOL) at ambient, 40°C, and 60°C; MIX at ambient, 40°C, and 60°C; then ligand selection A–D. The prediction dropdown offers 100% down in 10-point steps to the calculated intermediate %B, plus the preceding run's %B when that value is outside the list. The selected value defaults to the preceding run's %B. ACN/METHANOL and ligand choices use dropdowns; MIX is a free-text solvent field, and the entered mixed-solvent value is carried into its later temperature stages. Each stage recommendation remains active until its required %B sequence has been run with fewer peaks than the target. If the target is met at any stage, the ordinary decision tree takes over.

The Trials table adds suggested next-run rows directly below a run. The `OR` minimum/intermediate recommendation adds one selectable row; the `THEN` recommendation adds two fixed rows. Other recommendations add one suggested row when a next `%B` can be calculated. Each suggested row copies the source trial's method and column values, applies the prediction values, and uses the next sequential injection/trial number. The Decision cell remains blank until the next run is performed. Every suggested row has a Delete button. Suggested rows are display-only and are not included in later regression calculations.

The minimum `%B` regression uses only the applicable uploaded run series: runs with the same Group No., HPLC No., and solvent as the run being evaluated. An ambient run means **Set Temp = 25°C**. It uses the most recent cycle with successive 10-percentage-point decreases in `%B`, ordered by Injection No.; non-ambient runs and other solvents are excluded. At least three applicable ambient runs with usable data are required for an R²-checked minimum-%B fit; otherwise the tool returns `NA% (Not Enough Runs to Calculate Min %B/Intermediate %B)`. Ligand-name differences do not exclude otherwise matching runs. For each run, noise filtering is applied first: `t0` is the retention time of the first remaining peak, and `tR` is the retention time of the last remaining peak. Those filtered values are used to calculate `k = (tR − t0) / t0` and fit `log10(k) = a × %B + b`. The Extraction log includes a run table with `%B`, filtered `t0`, filtered `tR`, `k`, `log10(k)`, pressure, and fit status. If the fit has `R² < 0.99`, runs are removed one at a time only when the removal improves R², while retaining at least three points. A numeric prediction is returned only if the resulting fit meets `R² ≥ 0.99` and falls within the allowed 0–100% B range. The target retention is the maximum run-time specification; target `k` uses the average filtered `t0` of the retained points: `k = (target retention − average t0) / average t0`. Then target `log10(k)` is substituted into the fitted equation to solve `%B = (log10(k) − b) / a`, rounded to the nearest integer. Back-pressure is retained with each extracted run and included in the calculation log.

The intermediate `%B` is calculated only when the same applicable Group/HPLC/solvent series has more than four (at least five) ambient runs in its most recent successive 10-point decreasing-%B cycle. Each candidate must have a valid `%B`, noise-filtered peak count, last noise-filtered peak retention time, lowest resolution (minimum Rmin), and back-pressure. Candidate runs are ranked by the sum of four absolute normalized differences: peak count versus the target peak count, last-peak retention time versus maximum run time, lowest resolution versus the resolution specification, and back-pressure versus the maximum back-pressure specification. Each difference is divided by the absolute corresponding specification (minimum scale 1), so the four measurements contribute on comparable scales. The two lowest-scoring runs are selected; their `%B` values are averaged and rounded to the nearest integer. The extraction log shows each candidate's measurements, per-measurement score, combined score, and selection status.

Minimum-%B and intermediate-%B are recalculated from the applicable run history for each trial that needs a minimum/intermediate recommendation. Predictions are not frozen or shared between run series. Earlier predictions use only runs uploaded up to that trial; later runs from another Group/HPLC/solvent series cannot alter or supply its calculation. Minimum %B requires at least three usable ambient regression points; Intermediate %B retains its separate requirement of more than four ambient candidate runs. When either calculation lacks its required data, the UI displays `NA% (Not Enough Runs to Calculate Min %B/Intermediate %B)` instead of a numeric prediction.

For a `Decrease %B by 10` recommendation the next `%B` subtracts 10 percentage points. For a minimum-%B recommendation, the regression uses only the applicable Group No./HPLC No./solvent series and its latest sequential cycle of non-suggested ambient runs (Set Temp = 25°C), ordered by Injection No., with each `%B` step decreasing by 10 points. Ligand-name mismatches do not exclude otherwise sequential runs. At least three ambient runs with usable values are required. Noise filtering is applied before selecting `t0` as the first remaining peak's retention and `tR` as the last remaining peak's retention. Each usable run is converted to `K = (tR - t0) / t0`, then fitted as `log10(K) = a × %B + b`. When `R² < 0.99`, a run is removed only if doing so improves R², and at least three points are retained. A prediction is returned only when the resulting regression meets `R² ≥ 0.99` and the result falls within 0–100% B. The average filtered `t0` of the retained runs is used with the configured maximum run-time specification as the target last-peak `tR`; target `K = (target tR - average t0) / average t0`, then target `log10(K)` is substituted to solve `%B = (log10(K) - b) / a`. If fewer than three applicable ambient runs with usable data are available, Minimum %B displays `NA% (Not Enough Runs to Calculate Min %B/Intermediate %B)`. The predicted value is rounded to a whole percent. The Extraction log lists each run's `%B`, filtered `t0`, filtered `tR`, `K`, `log10(K)`, pressure, and fit status, followed by regression coefficients, removed points, average `t0`, target `tR`, target `K`, target `log10(K)`, and R².

The separate visual `Minimum %B calculation` panel has been removed. Minimum-%B calculation details remain available in the Extraction log; predictions are recalculated from each trial's applicable run history.

For simple header-row files, header matching is case-insensitive and allows common variants of:

- Conditions: `Ligand`, `Column Type`, `CoreShell`, `Pore Size (Å)`, `C Load (%)`, `Length (mm)`, `Ø (mm)`, `PS (µm)`, `Solvent`, `%B`, `Flow (mL/min)`, `Sample Conc (mg/mL)`, `Temp (°C)`, and `Wavelength (nm)`.
- Results: peak count, last peak retention time, resolution/Rs, and back pressure.

If peak count or last-peak retention time is not present, the tool can derive them from rows containing retention times: the number of rows is used as peak count and the largest retention time is used as the last peak. If several resolution values are present, the smallest is used as the worst-separated pair.

## Decision tree

The defaults are 7 peaks, 15 minutes, 1.4 Rmin, and 4000 psi. The decision tree uses the retention time of the last peak-table peak as its run-time measure; total file runtime is not shown as the decision runtime. If fewer than the target number of peaks are found, resolution remains displayed but is ignored by the decision. When last-peak retention is already at or above the maximum run time, the recommendation is `Jump to Minimum %B THEN, Intermediate %B`. Otherwise, the tool estimates last-peak retention after a 10-percentage-point decrease using the latest two runs up to the current run in the same sequentially decreasing-%B cycle and with the same Set Temp. If that estimate exceeds the maximum run time, it recommends `Jump to Minimum %B OR Intermediate %B`; otherwise it recommends `Decrease %B by 10`. If two suitable runs are not yet available for the estimate, it continues with `Decrease %B by 10` while the current last-peak retention remains below the maximum. When the peak target is met, last-peak retention longer than the maximum time goes to `Jump to SEL cycle` only when resolution is below specification; if resolution meets specification the output is `N`. For runs within the maximum time, resolution below specification also outputs `N`; resolution meeting specification recommends increasing flow until resolution reaches specification.
